# 便携生命周期验收标准

用户于 2026-09-28 明确的目标：插上能用，拔走清理电脑上的本次运行数据，再次插入或换电脑无需重新配置。此文是后续实现与验收要求，不表示这些能力全部已经实现。

## 数据归属

- U 盘保存唯一的长期配置，包括供应商、凭据、工具偏好和需要保留的会话。敏感内容应加密；拔盘不删除 U 盘上的长期配置。
- 电脑只使用本次运行独占的临时目录。不能依赖本机保留配置才能再次使用，也不能修改、覆盖或清理电脑原有的同名软件配置。
- 配置跨电脑、跨盘符恢复。解锁密码不属于重复配置；已经保存过的供应商、密钥和环境选择不得要求重新输入。
- 用户进一步明确：允许运行时使用本机，长期配置以 U 盘为准；CC Switch 只管理 U 盘上的 harness 配置，不接管电脑原有 AI 工具。

## 使用过程

1. 插入 U 盘，由用户启动入口；自动定位当前盘符，检查必要运行条件，解锁并恢复配置。
2. 运行期间，已保存的配置变更应及时、安全地写回 U 盘。对数据库必须使用一致性备份或其他经验证的机制，不能假定复制正在写入的文件就是有效备份。
3. 正常退出或安全拔出前，完成最终保存，结束本次工具进程，清理本次受管临时数据。
4. 直接拔盘时，驻留电脑的看护进程结束本次工具进程并清理本次临时数据；不得影响其他独立会话或电脑原有程序。拔盘后无法补写 U 盘，尚未写回的最新变更可能丢失。
5. 再次插入，在同一台或另一台满足运行条件的电脑上，从 U 盘恢复已保存状态。

## 边界与冲突处理

- “清理”指删除本项目管理的临时文件及结束其进程，不等同于存储介质物理擦除，也不承诺抹去 Windows 日志、分页或安全软件记录。
- 电脑断电时看护程序无法执行清理，不能承诺断电后立即清理。
- 保存失败且 U 盘仍在时，既有基础功能会保留会话以便恢复。正常成功退出的清理与保存失败的保留应明确区分；不能把保留恢复数据称为无残留。后续应设计加密恢复流程。
- 不依赖修改 CC Switch 源码或官方二进制；适配层独立维护。仅提供 portable ZIP 或修改工作目录不能算通过验收。
- 若某个第三方工具依赖本机安装、系统功能或管理员配置，应明确列出条件，不能宣称任意电脑即插即用。

## CC Switch 接入必须验证

- 首次启动就隔离路径，包括应用数据库、设置、目录指针、日志、界面缓存及其管理的 CLI 配置；不能先写入电脑原有目录再迁移。
- 在无既有配置和存在本机 CC Switch 配置的环境分别测试；本机原有配置保持不变。
- 使用合成凭据测试首次启动、改配置、正常退出、再次启动、盘符变化、换电脑和直接拔盘。
- 多开时分别拥有临时目录与进程；共享持久配置的写入需要协调，关闭或清理一份不能影响另一份。
- 上游升级后重复隔离验证，通过后才放行新版本。
