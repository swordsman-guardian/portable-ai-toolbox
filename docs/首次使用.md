# 首次使用

本项目当前为 v0.2.0-alpha.1。请从当前 release 页面下载源码 ZIP。它不是可直接运行的完整 U 盘镜像：其中没有第三方运行时、CC Switch、Claude Code、WebView2 或其他第三方程序。首次准备需要联网，下载优先使用官方来源；若使用镜像，也必须通过官方固定 SHA-256 校验，文件大小不能代替哈希校验。请只按发布页面明确列出的准备步骤操作。项目原创代码按 [MIT 许可证](../LICENSE) 发布；第三方许可和公开附件范围见[第三方许可与公开发布说明](第三方许可与公开发布.md)。

解压时把 ZIP 内最上层目录中的文件和文件夹平铺到一个工具箱根目录，确保 `AI.sh`（Linux）或 `AI.cmd`（Windows）与 `scripts/` 位于同一层。不要保留多套嵌套目录。Linux 可直接将该目录放在 U 盘根目录；Windows 先在准备机的全新目录中完成准备，再复制到 U 盘。

目标环境是 Windows 10/11 x64 与 Ubuntu 24.04 x64。Windows 11 Home x64（版本 10.0.26200）和 PowerShell 5.1 的独立空源码目录准备已通过；Windows 10 尚无实体机验证结果。其他 Linux 发行版和架构、不同系统策略及安全软件尚未全面验证。WSL 与 CI 的通过结果不能证明实体机都能运行。

## Linux：Ubuntu 24.04 x64

准备 Linux 运行文件需要 Ubuntu 24.04 x64、普通用户账户、联网，以及系统已有的 `bash`、`curl`、`tar`、`apt-get`、`dpkg-deb` 和 `ldd`。脚本只下载并解包依赖，不安装操作系统软件，也不应使用 root 运行。

1. 把源码 ZIP 解压到 U 盘根目录。下面假设工具箱根目录是 `/media/$USER/TOOLBOX`；请替换成实际挂载路径。

2. 在终端运行准备脚本：

   ```bash
   ROOT="/media/$USER/TOOLBOX"
   bash "$ROOT/scripts/bootstrap-linux.sh" "$ROOT"
   ```

   路径应指向已经存在、同时包含 `AI.sh` 和 `scripts/` 的目录。若路径含空格，命令仍可正常使用。首次准备会联网下载并验证 Linux x64 运行文件。

3. 如果系统的 AppArmor 限制阻止隔离启动，程序会先简短说明，再由 `sudo` 在本机终端询问**本机管理员密码**。这不是 U 盘主密码；输入直接交给系统 `sudo`，工具箱不会读取或保存它。按 Ctrl+C 可取消。授权失败或取消时不会解锁保险箱。

4. 准备结束后，从终端运行：

   ```bash
   bash "$ROOT/AI.sh"
   ```

   Linux 日常工作目录默认为 U 盘根目录下的 `workspace/`，不存在时会创建。菜单 1 使用该目录；菜单 2 允许输入另一个项目目录，直接回车仍使用 `workspace/`。已有项目文件会保留。U 盘根目录、用户主目录及工具箱运行数据目录不能作为项目目录。

5. 在工具箱菜单选择 CC Switch 离线或联网启动。初次解锁时按提示在本机创建 U 盘主密码，再在 CC Switch 中添加供应商、API 密钥和模型。离线菜单不能执行联网更新；添加或管理在线供应商时选择联网菜单。工具箱不会要求你为了初始化而执行真实 API 请求。

6. 让 CC Switch 所在的终端保持打开。另开一个终端，再运行 `bash "$ROOT/AI.sh"`，选择“启动 Claude Code”。如需其他目录，选择“选择工作目录并启动 Claude Code”。Claude 对一个新项目目录可能会询问是否信任；只对你信任的项目继续。

7. 使用完成后正常退出 Claude 和工具箱会话，等待保存完成，再关闭或锁定 CC Switch，最后安全弹出 U 盘。强制关机、终止进程或直接拔盘可能打断保存；软件不能保证强拔后完成清理。断盘后如提示有待恢复的加密会话，请重新连接同一 U 盘并按提示恢复。

### Linux 诊断

运行 `bash "$ROOT/AI诊断.sh"` 可查看工具箱、内核 user namespace 与运行时状态。诊断只读取状态，不需要 U 盘主密码，也不会发起真实供应商 API 请求。

### Linux 验证边界

Linux 完整准备脚本以普通用户身份在 WSL2 Ubuntu 24.04 x64 重跑成功；冷准备与 WSLg 图形启动也已验证，包含 Node 22.23.3、uv 0.8.22、CC Switch 3.20.4、Git、bubblewrap、Python 3.12.11 和 Claude Code 2.1.289。当前 WSL2 环境没有启用 AppArmor，因此这不代表真实 Ubuntu 实体机上的 AppArmor 授权体验；临时策略授权和撤销分支在 GitHub 托管 Linux runner 上验证过。其他桌面、系统策略和安全软件尚未全面验证，这些测试结果不构成对任意 Ubuntu 电脑的兼容保证。

## Windows：Windows 10/11 x64

Windows 准备机需要 Windows 10/11 x64、Windows PowerShell 5.1，以及 Visual Studio 的“使用 C++ 的桌面开发”工作负载。准备机需要该 C++ 工具链来编译原生适配器；日常使用准备好的 U 盘不需要安装 Visual Studio。

1. 把源码 ZIP 内最上层目录中的文件和文件夹平铺到准备机的一个全新目录，确保 `准备Windows.cmd`、`AI.cmd` 和 `scripts/` 位于同一层。不要在已经包含个人 `config/` 或 `sessions/` 的目录中运行准备入口。

2. 双击 `准备Windows.cmd`。入口会先检查 Windows PowerShell、系统位数、目录状态和 Visual Studio C++ 工具链；环境检查通过后才开始下载。下载优先使用官方来源；若使用镜像，也必须通过官方固定 SHA-256 校验，文件大小不能代替哈希校验。Node、Git、Python、uv、CC Switch ZIP、WebView2 CAB 和 Claude Code 按固定 SHA-256 或官方发布元数据校验。下载、解压和构建需要联网和数 GB 可用空间，完成时间取决于网络与准备机性能。本次 CC Switch ZIP 由本轮从官方 Release 获取并经入口固定 SHA-256 复核；匿名下载可能受网络速度影响。若准备失败，按终端提示修复后再在原准备目录重试；不要把未显示成功完成的目录复制到 U 盘。

3. 准备成功后，把准备目录内的全部文件和文件夹直接复制到 U 盘根目录，确保 `AI.cmd` 和 `scripts/` 位于同一层。此后在这份目录中配置和使用；不要再对已经含有个人设置、保险箱或会话的副本重跑准备入口。每份新的源码目录只进行一次完整准备。

4. 本次 Windows 独立空源码 fixture 的准备入口运行成功，Node 24.21.0、uv 0.12.17、Git 2.56.0、Python 3.12.14、CC Switch 3.20.4、WebView2 153.0.4234.48、适配器编译和 Claude Code 2.1.289 CLI 检查均通过。WebView2 按固定 SHA-256、Microsoft 签名及 257 文件清单核验；Claude Code 按官方 registry SHA-512 校验，并在隔离空配置中通过 `--version` 检查。完成回执再次检查成功，内置空配置没有变化，也没有创建主密码、供应商或发起 API 请求。CC Switch ZIP 使用本轮从官方 Release 获取的缓存，准备入口按固定 SHA-256 和解压文件再次验证；匿名下载通道未完整下载该 ZIP，仅完成 HEAD/分段探测。此次没有进行真实用户 GUI 或供应商 API 测试。

5. 在准备好的 U 盘上双击 `AI设置.cmd`，选择“10. CC Switch 接入”→“8. 解锁 / 打开原生 CC Switch（隔离联网）”。按提示在本机设置主密码，再在 CC Switch 原生界面添加供应商、API 密钥和模型。密码只在本机输入，不要发到聊天。配置供应商本身不要求发送真实 API 请求；菜单中的连通性测试会真实请求所选供应商，可能产生费用，只有主动选择测试时才会运行。

6. 保持 CC Switch 会话窗口运行，再从另一个终端或双击 `AI.cmd` 启动 Claude。首次使用时回车默认选择 U 盘上的 `workspace/`；这台电脑已有记忆工作目录时，回车会沿用上次目录，也可以输入或选择其他具体项目目录。使用完成后退出 Claude 并等待保存，再在 CC Switch 菜单锁定并保存会话；确认关闭后再安全弹出 U 盘。强制退出或强拔可能中断保存。

双击 `AI诊断.cmd` 可检查盘内 Claude 运行时的发现与启动状态。诊断不解锁保险箱、不读取供应商密钥，也不请求真实 API。
