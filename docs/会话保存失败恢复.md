# 会话保存失败后的恢复

正常保存成功后，本次会话的本机临时目录会清理。如果 U 盘仍可确认，但最后一次保存失败，程序会保留本机副本、显示目录及重试命令，并以失败状态结束。新窗口不会自动删除已标记为待恢复的目录。

1. 保留退出窗口显示的本机目录。不要在确认归档成功之前删除它。
2. 确认原 U 盘已接好、有剩余空间，归档目标可写。如果盘符改变，需要把重试命令中的工具路径和归档目标改到原盘的新盘符；不要误选其他磁盘。
3. 执行退出窗口给出的重试命令。命令会从保留目录再次保存到该会话自己的归档位置。若错误是配置文件 JSON 不完整，应先备份该文件，再处理报错；重复执行不会修复无效的文件内容。
4. 检查命令没有异常，结果中的 `failed` 为 0，并通过启动器重开原项目检查历史。保留标记不会因手动同步成功自动取消；确认内容完整后，才可手动删除这一个已关闭会话的目录。

窗口已关闭时，可在之前显示的临时目录中查看 `.session-owner.json`：`recoveryRequired` 表示需要恢复，`recoveryReason` 是失败原因，`recoverySourceDir` 是保存源目录，`recoveryArchiveDir` 是该会话归档目标。`guard` 目录中的日志也保留了错误线索。不要清空整个系统临时目录。

重试命令的形式如下，所有占位路径都需要换为本次会话记录的真实路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "盘符:\scripts\sync.ps1" -SourceDir "记录的 recoverySourceDir" -SessionsDir "记录的 recoveryArchiveDir" -Direction Push
```

这项保留机制针对保存失败。突然拔盘仍按拔盘流程结束进程并尝试清理本次会话，无法补写已经不可访问的 U 盘；它不是未保存内容的自动恢复保证。待恢复目录仍在当前电脑的临时位置，不受 U 盘携带保护，也可能被系统或其他清理软件移除，应及时处理。
