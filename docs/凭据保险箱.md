# 可移植凭据保险箱

保险箱将凭据映射加密为单个可拷贝文件。它使用用户输入的主密码和随机 salt 派生密钥，不绑定 Windows 用户或电脑；忘记主密码时没有恢复密钥。主密码只经 `SecureString` 参数交给本进程中的保险箱函数，不应传给子进程、环境变量或日志。凭据解锁后仍会短暂存在本进程内存中，因此保险箱不能保护已解锁的电脑或已被控制的进程。

## 加密格式

文件为 UTF-8 JSON，格式名 `portable-credential-vault`，版本 1。加密部分使用 PBKDF2-HMAC-SHA256（600,000 次迭代、随机 16 字节 salt）派生 64 字节材料，前 32 字节用于 AES-256-CBC/PKCS7，后 32 字节用于独立 HMAC-SHA256 key。每次写入生成随机 16 字节 IV。Encrypt-then-MAC 覆盖固定域分隔、版本、KDF 参数、salt、IV 和 ciphertext；MAC 验证成功后才进行解密。认证失败、错误主密码和解密失败都不会改写保险箱。

限制：文件最多 48 MiB，解密后的 UTF-8 JSON 最多 35 MiB，最多 256 个条目，名称最多 128 个字符，单个字符串值最多 35 MiB。PBKDF2 迭代数接受 600,000 至 1,000,000，超过范围的文件在派生密钥前拒绝。需要 Windows PowerShell 5.1 和 .NET Framework 4.7.2 或更新版本；若显式 SHA-256 的 PBKDF2 API 不可用，函数会报错，不回退到 SHA-1。

## PowerShell 接口

先点载入 `scripts/vault.ps1`。所有函数只接受 `SecureString` 主密码；`Read-PortableVault` 返回 `Secrets`（字符串到字符串的字典）及文件字节的 SHA-256 `Revision`。

```powershell
. "$PSScriptRoot\vault.ps1"
$password = Read-Host '保险箱主密码' -AsSecureString
$result = Read-PortableVault -Path $vaultPath -Password $password
# 修改 $result.Secrets 后，使用读取时的 Revision 执行乐观并发写入
$newRevision = Write-PortableVault -Path $vaultPath -Password $password `
    -Secrets $result.Secrets -ExpectedRevision $result.Revision
```

首次创建时，目标文件及 `.bak`、`.tmp` 恢复痕迹都必须不存在，并显式传 `-ExpectedRevision $null`。更新必须提供先前读取的 Revision；Revision 不一致时拒绝覆盖。不同窗口串行持有独占 `.lock` 文件，并在锁内比较 Revision。

`Get-VaultStatus -Path` 只查看存在状态、恢复痕迹和格式元数据，不解密。它返回 `Path`、`State`（`Absent`、`Present`、`RecoveryRequired`、`InvalidMetadata`）、`Exists`、`BackupExists`、`TemporaryExists`、`RestoreTempExists` 和 `Metadata`。状态为 `Absent` 才可初始化；出现 `.bak`（且主文件不存在）、`.tmp` 或 `.restore.tmp` 时应由用户明确选择恢复来源或检查现场。若主文件缺失，`Read-PortableVault` 不会自动选择恢复文件。执行 `Restore-PortableVault -Path ... -Password ... -Source Backup|Temp` 时，所选文件先通过认证和解密检查，再安装；已有主文件会移至 `.pre-restore-<哈希前缀>`，恢复成功后尚存的 `.tmp` 会移至 `.recovered-temp-<哈希前缀>`，加密材料均予保留。错误主密码不改变主文件或恢复文件。

写入先在同目录创建 `.tmp` 并 flush，然后将旧主文件备份至 `.bak` 并移除主路径，再将暂存文件移为主文件。中断后应检查 `Get-VaultStatus` 并明确选择 `Backup` 或 `Temp`；任何自动恢复之外的未知现场都保持原样。恢复验证和读取会尽力清理临时字节及字典引用；.NET 托管字符串不能承诺物理擦除。`.bak` 是上一版加密快照，不是主密码重置机制。

## 合成数据测试

在 Windows PowerShell 5.1 中运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\test-vault.ps1`。测试只在系统临时目录生成合成凭据，覆盖正确读写、错误密码、篡改认证、并发过期 Revision、提交中断后的显式恢复、恢复文件保留以及 32 MiB 字符串值往返。

实现依据：Microsoft Learn 的 [Rfc2898DeriveBytes](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes)、[.NET cryptography model](https://learn.microsoft.com/en-us/dotnet/standard/security/cryptography-model)，以及 OWASP 的 [Cryptographic Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html) 和 [Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。OWASP 优先推荐 AEAD；当目标框架未提供可用 AEAD API 时，允许 CBC 配合 Encrypt-then-MAC。该设计保护静态文件，不保护解锁期间的内存凭据。
