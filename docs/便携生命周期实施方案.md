# 便携生命周期实施方案

目标：配置在 U 盘长期保存，电脑仅承载本次临时运行；退出或拔盘清理受管临时数据，下次插入恢复已经保存的配置。CC Switch 使用官方原包，适配代码独立维护。

## 本轮分工

所有实施与独立审查子代理使用 GPT-6 Luna，主控负责集成、回归和最终汇报。

| 工作 | 交付 | 验证 |
| --- | --- | --- |
| 加密配置存档 | 复用现有保险箱加密，保存已停止写入的应用配置目录，使用相对路径恢复到新目录 | 错误密码、篡改、并发旧版本写入、路径越界与覆盖保护 |
| 拔盘生命周期 | 用合成应用实际运行现有看护与会话清理流程，修复发现的缺陷 | 模拟卷身份消失、子进程退出、临时目录清理、独立实例保留 |
| CC Switch 隔离验证 | 核查官方可用入口，提供不启动真实 GUI 的 Windows 路径探针 | 区分环境变量重定向与系统目录解析，记录待完成的 GUI 写入验证 |
| 主控集成 | 包完整性验证、统一测试入口、使用与验收记录 | Windows PowerShell 5.1 回归及 Luna 独立审查 |

## 存储方案

敏感配置存档使用现有加密保险箱格式，并发保存使用版本校验。文件清单只保存相对路径，可以恢复到另一处盘内目录。文件内容原样保存：若配置内容自身含绝对机器路径，仍需对应应用适配器在启动时重新生成，不能把文件恢复成功等同于换机自动可用。还原仅写入新建或空目录，拒绝符号链接、目录联接、越界路径与覆盖已有配置。

第一版只保存停止写入的、小型配置目录。它不等于数据库在线备份，不负责把正在运行的 SQLite 文件直接复制成有效存档。会话历史仍由已有归档流程处理。CC Switch 最终持久化哪些目录、如何安全保存运行中的数据库，须随其隔离方案一起验证。

## 接入决策

用户补充明确：程序和运行缓存可以放本机，长期配置应保存在 U 盘；CC Switch 只能修改 U 盘上的 harness 配置，不应接管本机原有工具。因此默认采用独立适配层，不把沙盒作为默认使用前提。应核实程序实际使用的系统目录、界面缓存和被管理工具目录，不能仅凭设置 HOME 或 APPDATA 就认定完成接入。

本轮可用的供应商导入入口只向本工具箱的 providers 文件和加密保险箱写入，过滤输入中的工具路径及 hooks。手动配置存档入口恢复到 `harness/restored-profiles/<存档名>`，不允许交互菜单选宿主目录；低层恢复 API 保留恢复到调用方明确受管临时目录的能力，以备后续自动启动集成。

在首次启动隔离尚未验证时，保持 GUI 禁用。加密存档、生命周期测试和包校验的完成，都不能替代 GUI 隔离验收。不会改宿主全局目录、注册表或原有 CC Switch 配置来制造“便携成功”的表象。

## 本轮完成定义

新增模块具备可运行接口与真实边界测试，原有功能回归通过，独立审查发现的问题处理完毕，文档明确哪些功能已完成、哪些仍需验证。硬件拔盘、断电、陌生电脑和 CC Switch GUI 的实际运行结果，只能在执行对应测试后记录为通过。

## 实现落点与接入顺序

`scripts/cc-switch-context.ps1` 提供独立于官方包的配置准备模块。它把 CC Switch 自身设置定位到 `config/cc-switch/home/.cc-switch`，把八个 CLI 配置目录定位到 `harness/cc-switch/<工具名>`；Gemini 的实际配置目录是其中 `gemini/.gemini`，因为其 home 环境变量还会再追加 `.gemini`。每次初始化根据当前 U 盘根重新生成受管路径，保留其它设置；候选路径不可通过目录联接跳到本机。模块不会启动官方程序。

运行时 profile、AppData、临时文件和 WebView2 目录安排在本次本机会话中。返回的环境变量集合是覆盖项，尚不是完整且已验证的进程环境。尚未将这些候选目录接入现有 Claude 启动时的供应商和设置生成流程，不能把预置八个目录理解为已经接入八种 harness。

`guardian.ps1 -StorageMode DirectUsb` 提供配置直接写盘的看护模式。它验证声明的配置目录严格在 U 盘根下、不经过目录联接，并继续使用独立 Job 与会话目录；正常退出或模拟拔盘会结束本次进程并清理本次运行目录。此模式不调用归档同步，不声称数据库已提交或刷盘成功；它也不是对应用任意文件写入的权限沙箱。原有 Archive 模式不变。

后续原生 GUI 接入顺序是：先确认普通界面操作没有绕过这些路径，再完成单实例占用与进程环境组装、现有供应商配置衔接、实际界面读写验收。敏感数据库的加密保存与恢复还需确定一致性方案；本轮手动存档只适用于应用停止之后，不能代替自动持久化。最终才把已验证的启动入口接入设置菜单。
