║            便携 AI 工具箱  ——  使用说明                    ║
╚══════════════════════════════════════════════════════════╝

这是一个"插上就能用"的 AI 编程工具箱。它把运行时（Node / Git /
Python / uv）和 Claude Code 全都装在这个 U 盘里，插到任何一台
Windows 电脑上都能直接用，不需要在那台电脑上安装任何东西。


────────────────────────────────────────────────────────────
 首次准备（只做一次，在你自己电脑上）
────────────────────────────────────────────────────────────

  1. 双击  AI设置.cmd
  2. 选「安装 / 更新 harness」把 Claude Code 装进 U 盘
  3. 选「凭据保险箱」创建 / 迁移，并在本机设置主密码
  4. 在保险箱中选「添加 / 更新一个凭据」，填入供应商对应的变量名和密钥
     （例如 ALIYUN_BAILIAN_API_KEY；输入密钥时不可见）

  如果 runtime 目录是空的，说明运行时还没装：
    手动运行下面这条命令（一次性，约 700MB）
      powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1


────────────────────────────────────────────────────────────
 日常使用（在任何一台电脑上）
────────────────────────────────────────────────────────────

  双击  AI.cmd；启用保险箱后，按提示输入主密码

  就这样。它会：
    · 把运行环境准备好，全程不碰这台电脑的设置
    · 打开 Claude Code
    · 你正常干活就行

  ★ 每次启动它都会问一句「要处理哪个目录？」：
      回车          = 沿用上次那个（直接显示给你看）
      输入/粘贴路径 = 换成这个
      输入 ?        = 打开文件夹选择框
    上次那个会按电脑记住，所以同一台机器上回车就够。

  ★ 拖文件夹到 AI.cmd 上松手时，不会再问 —— 那是你明确指定了。

  想直接对某个项目动手，不用等它问：
    把那个项目文件夹  拖到 AI.cmd 上  松手
    它以那个目录为工作目录启动，并记住

  没选、或者拖拽的话，它会落在 U 盘上的工作区（E:\workspace）。

  ★ 不要选「当前用户的主目录」当工作目录。原因：Claude Code 会把
    <工作目录>\.claude\ 当成项目配置加载，而主目录下的 .claude 正是
    它自己的用户配置目录 —— 结果会把宿主已有的目录授权、插件、hooks
    全都带进来。程序会拦住这种选择并提示你换一个。

  想换个目录 / 换供应商 / 看状态：
    双击  AI设置.cmd

  ★ 选了带项目配置的目录（里面有 .claude\ 或 CLAUDE.md）时：
    · 那是正常的项目配置，会被加载 —— 这正是它该有的行为
    · Claude Code 会就「是否信任该工作区」弹窗问你，不信任就别继续
    · 项目配置可以授权项目外的目录、也能定义启动时执行的 hook，
      所以只在你信得过的项目里这么用


────────────────────────────────────────────────────────────
 怎么结束
────────────────────────────────────────────────────────────

  可以同时打开多个窗口。每个窗口有自己的配置、进程和归档，
  关闭一个窗口只清理这个窗口；拔掉 U 盘会结束本盘的所有会话。

  两种结束方式：

    · 正常退出 Claude Code（/exit 或 Ctrl+C）
    · 意外拔掉 U 盘时，守护会尝试终止和清理本次会话

  建议正常退出，看到保存完成后再拔盘。直接拔盘无法保存尚未归档的内容。

  正常保存成功后它会：结束本次会话的进程树、清空本机临时目录，
  并打印一行清理结果给你看。

  如果 U 盘仍在但最终保存失败，会保留本次临时目录并显示重试命令。
  后续启动不会自动删除这份待恢复副本。请先完成恢复，再清理该目录；
  具体步骤见 docs\会话保存失败恢复.md。

  ★ 它绝不会去动这台电脑上其他的程序。哪怕这台电脑上
    本来就装着 Claude Code 并且在运行，也不会被误杀。


────────────────────────────────────────────────────────────
 会话记录存在哪
────────────────────────────────────────────────────────────

  会话记录（对话历史、文件编辑历史）会定期从本机搬回 U 盘，
  按电脑分开存放：

    sessions\<电脑标识>\<工具标识>\runs\<会话标识>\

  每个窗口独立写入归档。再次启动会恢复当前项目的历史，
  同时兼容之前按电脑保存的旧归档。对同一路径的不同历史版本，
  恢复会选择有效的较新版本，原始归档都会保留；不会自动拼接分叉对话。

  换一台电脑用，只会加载属于那台电脑的历史，不会互相混淆。

  注意：AI 对这台电脑上项目的修改是会保留的 —— 那正是你用它的
  目的。被清掉的只有"我们带来的东西"（临时文件、进程）。


────────────────────────────────────────────────────────────
 已知限制（说清楚，别指望超出这个范围）
────────────────────────────────────────────────────────────

  · 本盘是 FAT32，因此有两处特例（都已绕开，不影响使用）：
      - uv python install 不可用（FAT32 不支持它要建的链接目录）
        盘上已预装好 Python，直接用即可
      - Claude Code 的 postinstall 跑不了（要建硬链接）
        安装时已用 --ignore-scripts 跳过，并修好了启动指向

  · 会话文件先写本机，每 30 秒尝试搬回 U 盘。30 秒是调度间隔，
    并非最大丢失保证；同步失败、慢盘或突然断电时可能丢失更多。
    归档保留恢复副本，但不能保证 FAT32 突然断电时绝不损坏。

  · 删除不等于物理擦除。拷到本机临时目录的东西在被删之前是
    真实写入过磁盘的，SSD 上删掉仍可能残留可恢复的块。它能保证
    的是尽量缩短临时数据存在时间，并用进程 Job 收尾；清理失败会提示。

  · 如果目标电脑上有企业管控的 Claude Code 策略
    （C:\ProgramData\ClaudeCode\managed-settings.json），
    那套策略会生效。这是设计如此，绕不过也不该绕。

  · 新增凭据保险箱：AI设置 → 9，设置主密码并迁移。
    迁移成功会重新解密核对，再删除旧 keys.env；删除不等于物理擦除。
    未主动启用前，现有 keys.env 仍是明文。忘记主密码无法解密。
    保险箱保护凭据文件，不加密项目、对话历史或运行中的进程内存。

  · Python/uv 默认使用内置解释器，项目的版本要求会单独检查。
    项目环境在本次临时工作目录中建立，不替换项目原有的 .venv。
    创建虚拟环境不等于已安装项目依赖，界面会区分这些状态。
    本版不自动下载其他 Python 版本，也不自动安装项目依赖。
    详细用法见 docs\Python环境管理.md。

    每个窗口的 Python/uv 环境绑定启动时选择的项目。
    换另一个项目请新开窗口，仅在终端切换目录不会自动更换环境。

  · AI设置 → 10 可导入选定 Claude settings JSON 中的供应商到保险箱。
    此入口只写 U 盘工具箱的供应商配置和保险箱，不接管本机安装的工具。
    菜单 6 可打开隔离的原生 CC Switch，与本机版本同时使用，无需安装。
    首次设置配置主密码，之后解锁即可恢复；配置加密保存在 U 盘。
    同一解锁会话可反复打开窗口，无需再次输入密码；菜单 7 保存并锁定。
    菜单 4 可让新 Claude 窗口读取盘内 CC 当前供应商，原窗口不受影响。
    菜单 6 离线管理配置；菜单 8 联网并检测供应商连通性。原生代理尚未接通。
    联网窗口不自动使用本机系统代理；切换联网 / 离线前先选 7 锁定。
    本机运行副本在使用时为明文，正常退出会清理。保存/清理失败会明确报错。
    突然拔盘只能保留此前成功快照；免安装不代表兼容所有电脑或管控策略。
    加密、迁移和恢复说明见 docs\CC-Switch加密接入验收.md。
    AI设置 → 11 可查看环境和待恢复会话；更多工具适配后续再增加。

  · AI设置 → 12 可手动保存 / 恢复加密配置存档。
    先关闭应用，再选择其小型配置文件夹（最多 16 MiB、512 个文件）。
    存档保存在 U 盘 config\app-profiles；恢复到盘内
    harness\restored-profiles\<存档名>，不能覆盖非空目录。
    此通用存档入口与 CC Switch 的专用加密会话分开，不是运行中数据库的实时备份。
    方案与本轮验收见 docs\便携生命周期实施方案.md。


────────────────────────────────────────────────────────────
 目录里都有什么
────────────────────────────────────────────────────────────

  AI.cmd            直接模式，双击就进
  AI设置.cmd        配置模式：装 harness / 选目录 / 换供应商 / 自检
  使用说明.txt      本文件

  runtime\          便携运行时（Node / Git / Python / uv）
  npm-global\       harness 装在这里
  harness\          harness 与供应商的配置
  config\           keys.env（密钥）、settings.json
  sessions\         会话归档，按电脑分开
  scripts\          所有脚本
  logs\             运行日志，出问题时看这里
  docs\             技术说明与验证清单


────────────────────────────────────────────────────────────
 出问题怎么办
────────────────────────────────────────────────────────────

  1. 双击 AI设置.cmd → 选「运行自检」，它会逐项告诉你哪里不对
  2. 连不上或报模型错误 → 选「测试中转连通性」
     它会真发一次请求，把模型的回复打给你看。通了就是密钥和
     中转都没问题，问题在别处。
  3. 看 logs\ 目录下最新的日志
  4. 技术细节见 docs\ 目录（尤其是 docs\实现笔记.md）
